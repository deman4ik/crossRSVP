# CrossRSVP v0.5.0: проверка перед публикацией

Дата: 7 сентября 2026 года. Задача: [#12](https://github.com/deman4ik/crossRSVP/issues/12).
Публичный релиз, push и тег не выполнялись. Название подготовленного релиза:
**CrossRSVP v0.5.0 — X3, X4 и X4 Pro**. До аппаратных испытаний сохраняется отметка pre-release.

## Реализация

На X4 Pro добавлена сенсорная панель RSVP: явный запуск, шаг, перемотка на пять
групп, уменьшение/увеличение темпа, настройки и возврат в Paged Mode. Касание
области чтения ставит воспроизведение на паузу. Отпускание этого касания не
нажимает появившуюся кнопку. Недоступные в текущем состоянии запуск и шаг
не показываются и не принимают касания. Панель скрывается при запуске, но её место остаётся
зарезервированным, поэтому ORP не перемещается.

Системная панель освещения приостанавливает сессию до открытия и отменяет
ожидающую команду запуска. Закрытие освещения и настроек возвращает ту же
сессию на паузе. Настройки применяются без пересоздания сессии и потери текущей
группы. У X3/X4 сохранено логическое кнопочное управление; сенсорная панель
выделяется только на устройствах с touch capability.

Новая панель создаётся один раз через `makeUniqueNoThrow` и освобождается с
активностью. Отдельный framebuffer и покадровые heap-буферы не добавлены.
Буфер метрик SD-шрифта переиспользуется после возврата из настроек; при нехватке
памяти сохраняется существующий отказ от группировки. Фактический свободный heap
на устройствах не измерялся.

## Проверки

- Прошивки: все три release-профиля собраны успешно после финальных правок.
  X3/X4 собраны с `-j 1`, Pro — с `-j 8` на 12-поточном хосте.
- Host suite: **299/299**. Включены отмена ожидающего запуска без потери других
  команд и изменение настроек только на паузе с сохранением текущей группы.
- Симулятор X3: 15 сценариев; кнопки, группировка, Paged ↔ RSVP, границы,
  fallback, задержка refresh, восстановление и четыре ориентации.
- Симулятор X4: те же 15 сценариев, с проверкой профиля X4 и геометрии 480×800.
- Симулятор X4 Pro: 13 сценариев настоящих синтетических касаний/жестов,
  включая все действия панели, системное освещение, возврат из настроек,
  сохранение позиции после сна, границы, fallback и четыре ориентации.
- Дополнительно на Pro: 8 сценариев шрифта 12/18 pt во всех четырёх ориентациях;
  шаг, запуск, пауза, геометрия снимков и визуальная проверка читаемости группы.
  Итого 54 сценария (15 + 15 + 13 + 8 + 2 + 1). Снимки крайних размеров — в
  `artifacts/crossrsvp-x4pro-v0.5.0/simulator/`.
- Длинный кириллический токен (190 байт) на Pro: два сценария в портретной и
  альбомной ориентации подтверждают остановку и возврат в Paged Mode без пропуска.
  Снимки и логи — в `artifacts/crossrsvp-x4pro-v0.5.0/simulator/`.
- Стандартное меню Pro: дополнительный сценарий More → RSVP → Paged Mode
  при `readerMenuStyle=1` прошёл. Основные сценарии используют меню списком (`0`).
  Доказательства — в `artifacts/crossrsvp-x4pro-v0.5.0/simulator-toolbar/`.
- ORP на Pro: сравнение положения направляющих на снимках «пауза → чтение →
  пауза» во всех четырёх ориентациях. Просмотрены портретная и альбомная панели,
  возврат из настроек и экран границы главы.
- Упаковщик: три модели, варианты CPPDEFINES, точное совпадение SHA-256 и отказ
  при неверном имени модели/версии.

Логи, BMP-снимки и `summary.json` находятся в
`artifacts/crossrsvp-<device>-v0.5.0/simulator/`; общие логи —
`artifacts/crossrsvp-v0.5.0/`. `summary.json` содержит хеш фактически запущенного
симулятора. Значения heap 65536/32768 в этих логах заданы инъекцией и **не являются
измерениями памяти**.

## Воспроизведение

Квалификация исключает пользовательский `platformio.local.ini`: локальная копия
`platformio.qualification.local.ini` совпадает с `platformio.ini`, кроме пустого
`extra_configs`. Пользовательские настройки не изменены. Перед сборкой установить
`requirements-platformio.txt` в Python из `pio system info`.

```sh
python3 -c 'from pathlib import Path; p=Path("platformio.ini"); Path("platformio.qualification.local.ini").write_text(p.read_text().replace("extra_configs = platformio.local.ini", "extra_configs ="))'
pio run -c platformio.qualification.local.ini -e simulator_x3 -e simulator_x4 -e simulator_x4pro
python3 scripts/qualify_rsvp_simulator.py --device x3
python3 scripts/qualify_rsvp_simulator.py --device x4
python3 scripts/qualify_rsvp_simulator.py --device x4pro
pio run -c platformio.qualification.local.ini -e rsvp_x3_release -e rsvp_x4_release -e rsvp_x4pro_release -j 1
cmake -S test -B build/test
cmake --build build/test --target RsvpTest -j 4
ctest --test-dir build/test --output-on-failure -j 4
```

На этом macOS использованы PlatformIO 6.1.19, его Python 3.14.7 и отдельное
окружение pioarduino Python 3.12.14. Для сборки S3 понадобилась установка
`toolchain-xtensa-esp-elf@14.2.0+20251107`. Сбой повторной загрузки уже установленного
`pioarduino-core` устранён запуском с `UV_OFFLINE=1`, использующим готовый кеш
Python-зависимостей; на новом компьютере сначала нужна обычная установка зависимостей.
Архив Xtensa получен с официального `dl.espressif.com/github_assets/` вместо
медленного GitHub; SHA-256 из `tools.json` совпал:
`9a0f6f4d83ff39af41f1d2ebbf4683668c95d4a47a3bf5b1fa74eef80f3af1bb`.

Закреплённые исходники SDK:

- freeink-sdk: `68425f8eec1246a0be0c0f311540f60ad733fa76`;
- simulator: `6aa3b5476f783953bff4ae8aa0b84d9a64dd07ef`;
- конфигурация платформы: pioarduino `55.03.37`.

## Границы подтверждения

Физические X3, X4 и X4 Pro не подключались. Не проверены GT911 и Home на реальной
плате, освещение, RTC/IMU, SDMMC/USB MSC, ток сна, heap/PSRAM, прошивка/откат и
качество e-ink на конкретных ревизиях панели. Матрица возможностей и инструкция
аппаратной проверки находятся в `docs/rsvp-device-audit.md` и
`docs/rsvp-release-installation.md`. X4C не входит в этот комплект.

Один контакт при задержанном refresh проверен. Более жёсткий эксперимент
«короткий Play и следующий swipe в течение одного задержанного кадра» не включён
в прошедшую матрицу: закреплённый симулятор хранит один `TouchState` и при обработке
нескольких просроченных событий заменяет предыдущее касание следующим до передачи
ввода прошивке (`simulator/src/HalGPIO.cpp`, `processSyntheticEvents`). Это ограничение
эмуляции не доказывает сохранность нескольких последовательных контактов на плате.
Отмена уже принятого запуска проверяется host-тестами очереди; пауза перед системной
панелью — отдельным сценарием симулятора.

Для первого непомещающегося слова в логе ожидаемо появляется прежняя диагностика
`Failed to save RSVP checkpoint`: ни одна RSVP-группа ещё не подтверждена. Снимок
Paged Mode подтверждает сохранение слова на странице; эта строка не считается
доказательством успешной записи checkpoint.

В native-сборках остаются прежние предупреждения о неполных switch в
`WifiSelectionActivity.cpp` и `EpubReaderActivity.cpp`; к новому управлению они
не относятся. В S3-сборке зависимость WebSockets также предупреждает об
устаревшем `NetworkClient::flush()`; исходники зависимости не менялись. Итоговые размеры и контрольные суммы образов приведены в
`docs/rsvp-release-notes.md` и `artifacts/crossrsvp-v0.5.0/SHA256SUMS`.
