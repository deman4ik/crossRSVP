# Ограничения RSVP по времени обновления

Статические потолки ниже являются предварительными номинальными значениями для
настройки RSVP. Это не минимальные гарантированные времена обновления и не
результаты полной температурной или аппаратной квалификации. При воспроизведении
блокирующий `BUSY`-wait драйвера сохраняется: если обновление дольше базового
интервала, следующее слово показывается после готовности панели, без пропуска
слов.

| Модель и путь | Номинальное FAST-время | Потолок RSVP |
| --- | ---: | ---: |
| X3, UC8253 | 435 мс | 130 слов/мин |
| X4, SSD1677 | 500 мс | 120 слов/мин |
| X4 Pro, SSD1677 | 500 мс | 120 слов/мин |
| X3 UC8279d, X4/X4 Pro UC8179 или UC8279, неизвестная партия | не подтверждено | 100 слов/мин |

Потолок считается как `floor(60000 / nominal_ms)`, затем округляется вниз до
шага 10 слов/мин. Для fallback 100 слов/мин используется базовый интервал
600 мс; это консервативная политика, а не измерение панели.

В [SDK revision `fde240faaeae6c340dacd435a4f77d2ef2f82dfd`](https://github.com/Free-Ink/freeink-sdk/tree/fde240faaeae6c340dacd435a4f77d2ef2f82dfd) для профилей X3, X4
и X4 Pro выставлен `displaySpiHz = 10 MHz` (`BoardConfig.h:837-855, 890-893,
1572-1573`). Числа 435 и 500 мс были получены/указаны в более ранней линии
драйверов и не являются повторным измерением на этой конфигурации SPI. Перед
аппаратным выпуском их нужно подтвердить логами; снижение SPI может добавить
время передачи framebuffer поверх waveform. Это уточнение не меняет текущую
предварительную политику потолков.

## Основания

- Реальный X3 UC8253: комментарий драйвера указывает около 435–436 мс для
  прогретого FAST-пути (`freeink-sdk/libs/display/FreeInkDisplay/src/driver/Uc8253X3Driver.cpp:147-148`).
  История SDK фиксирует это как измерение на X3: [commit b17beee](https://github.com/Free-Ink/freeink-sdk/commit/b17beee0c870c69bab5c5032cee03724ee07795c).
- X4 SSD1677: штатная последовательность `0xFC` описана в драйвере как около
  500 мс (`freeink-sdk/libs/display/FreeInkDisplay/src/driver/Ssd1677Driver.cpp:48-50`).
  Быстрый `0x1C` shortcut отключён по умолчанию и не используется для этого
  потолка (`Ssd1677Driver.cpp:109-127`); его выигрыш около 77 мс был подтверждён
  только для отдельного opt-in пути: [commit eaa73d5](https://github.com/Free-Ink/freeink-sdk/commit/eaa73d5b9a7fc6ce39b7aff751ee6884e268750e).
- X4 Pro имеет несколько партий контроллеров: SSD1677, UC8179 и UC8279
  (`freeink-sdk/docs/xteink-x4pro-support.md:1-18`). Поэтому значение 500 мс
  переносится только на SSD1677-путь. Для UC8179/UC8279 в SDK нет подтверждённого
  времени; их драйверы требуют отдельной проверки.
- Good Display для панели SSD1677 GDEQ0426T82 публикует partial refresh 0,42 с:
  [официальная спецификация панели](https://www.good-display.com/product/938.html).
  Это характеристика панели при заданных условиях, а не измерение конкретного
  X4/X4 Pro. В настройках используется около 500 мс, потому что именно такую
  последовательность `0xFC` и длительность задаёт текущий драйвер по умолчанию.

Очистка экрана не является рабочим FAST-бюджетом: HAL указывает для HALF около
1720 мс (`lib/hal/HalDisplay.h:16`), а X3-драйвер отдельно документирует широкий
диапазон формы волны (`Uc8253X3Driver.h:56`).

## Квалификация

После получения серийных логов нужно считать распределение фактических FAST
обновлений и применять более строгую формулу
`floor(60000 / (p95 + 100))`, округляя вниз до 10 слов/мин. Запас 100 мс
отделён от текущих номинальных потолков и предназначен для отдельного
квалификационного решения.
