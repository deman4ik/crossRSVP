# Измерение скорости RSVP на X3

Диагностический образ **0.8.0-speedtest.1** предназначен **только для Xteink X3**. В обычной прошивке
потолок остаётся 130 слов/мин для UC8253 (100 для неопределённого профиля).
Этот потолок — предварительная настройка, а не замер вашего экземпляра.

## Что изменено в тестовом образе

- В RSVP доступны **50–600 слов/мин** с шагом **25**. Новый вход в RSVP начинается
  со 100 слов/мин. Кнопки **Влево/Вправо** уменьшают/увеличивают заданную скорость.
  Названия кнопок логические: действует ваша раскладка.
- Верхняя строка помечена **ТЕСТ RSVP**. Вторая показывает фактические
  **кадры в минуту** и среднее время FAST-обновления экрана в **мс**.
  Показатели относятся к текущему непрерывному отрезку с одной скоростью;
  на паузе сохраняется последний результат. На экране он отстаёт на один кадр.
- Высокая скорость задаётся кнопками внутри RSVP. Общая настройка скорости
  остаётся обычной; возвращение из настроек сохраняет тестовую скорость.
  Тестовое значение не записывается в обычные настройки.
- В Serial выдаются строки `[RSVP-SPEED]` с временем обновления, полным временем
  от начала отрисовки до готовности экрана, интервалом между кадрами и свободной
  памятью. Текст книги в эти строки не попадает.
- Ожидание готовности панели **BUSY** и завершение работы драйвера сохранены.
  Если экран не успевает, рост заданной скорости перестаёт увеличивать фактическую.
  Никакие слова не пропускаются для достижения заданного числа.
- Волновые формы, частота SPI и регулярная очистка экрана не изменены.
  Диагностика использует менее 128 байт счётчиков в объекте чтения, без дополнительных
  heap-выделений и без записи замеров на SD во время показа слов.

## Установка

1. Сохраните копию SD-карты и файл предыдущей прошивки X3.
2. Сверьте SHA-256 скачанного `.bin` с приложенным `SHA256SUMS`.
3. Скопируйте диагностический `.bin` и `rsvp-speed.epub` в корень SD-карты.
4. На X3 откройте **Настройки → Система → Обновление системы с SD-карты**,
   выберите диагностический файл, подтвердите и дождитесь перезапуска.
5. Откат: выберите прежний файл X3 тем же способом. Не используйте файл X4 Pro.

## Как найти практический предел

1. Выключите **Группировать короткие служебные слова**. Откройте `rsvp-speed.epub`:
   там 720 коротких слов без пунктуации и промежуточных абзацев. Это отделяет
   ограничение экрана от пауз на длинных словах и знаках препинания.
2. Включите RSVP: меню книги → **Прочее → Режим чтения RSVP** (или строка
   **Режим чтения RSVP** в меню-списке). Нажмите **Подтвердить** для запуска/паузы.
3. Сначала оцените 100, затем 150, 200, 250, 300 и при необходимости 400–600 слов/мин.
   После каждой смены скорости дайте пройти хотя бы **60 слов**.
   Запишите заданную скорость, фактические кадры/мин и время экрана.
4. Отметьте, когда число кадров/мин перестаёт расти, появляются мешающие следы
   предыдущих слов или текст становится трудно различать. Пауза, шаг и возврат
   к странице работают обычным способом.
5. Повторите несколько прогонов на удобной скорости, затем проверьте обычную
   книгу с привычными паузами и группировкой. Измерительный предел и удобный
   темп чтения — разные результаты.

Первые кадры после запуска используйте для прогрева. Очистка экрана дольше FAST
и уменьшает общий темп. Фактическое время зависит от партии контроллера,
температуры и состояния панели; одного прогона недостаточно для общего лимита
всех X3. Укажите версию/контроллер из стартового Serial-лога, ориентацию,
шрифт, температуру помещения и замечания по качеству изображения.

## Запись и разбор замеров

Подключите X3 по USB, выберите его последовательный порт и сохраните вывод.
На компьютере с PlatformIO из каталога исходников:

```sh
pio device monitor -b 115200 --filter log2file
python3 scripts/analyze_rsvp_speed.py /путь/к/serial.log
```

Либо запишите лог любым Serial-терминалом (115200 baud). Скрипт
`analyze_rsvp_speed.py` из комплекта работает на Python 3 без сторонних библиотек.
Чтение по UART и вывод логов могут немного влиять на общий темп; это отражается
в фактически измеренных интервалах. Время `refresh_ms` замеряется до вывода лога.

В отчёте сравнивайте общий темп с учётом очистки и FAST отдельно. Первый кадр
каждого непрерывного запуска не имеет интервала; паузы пользователя и смены
скорости разделяют запуски. `60000 / p95(refresh_ms)` — лишь оценка по времени
FAST без отрисовки/очисток, а не рекомендованная безопасная скорость.

Пришлите Serial-лог и короткую таблицу «задано / фактически / читаемость и следы».
По ним можно будет обоснованно пересмотреть обычный потолок X3.

## Воспроизводимая сборка и ограничения проверки

```sh
pio run -e rsvp_x3_speedtest
pio run -e simulator_x3_speedtest
python3 -m unittest discover -s test/python -p 'test_analyze_rsvp_speed.py'
```

Симулятор проверяет диапазон 50–600, управление, границы измерительных запусков
и интерфейс. Его искусственная задержка обновления не измеряет экран X3.
Физическая проверка выполняется владельцем устройства; тестовый образ не
объявляется аппаратно проверенной или обычной стабильной прошивкой.


### Результат проверки перед передачей

- 150 тестов RSVP и 4 теста анализатора прошли.
- `pio check -e rsvp_x3_speedtest`: дефектов не найдено.
- Симулятор X3: проверены 50 и 600 слов/мин, ограничение на концах диапазона,
  пауза/продолжение, сохранность обычной настройки скорости и все 4 ориентации.
- При искусственном ожидании экрана 300 мс и заданных 600 слов/мин измеренный
  темп в симуляторе составил около 191 кадра/мин. Это проверка счётчиков и ожидания
  экрана, **не результат измерения X3**.

Для повторения сценария после сборки симулятора:

```sh
python3 scripts/qualify_rsvp_speedtest.py \
  --program .pio/build/simulator_x3_speedtest/program \
  --output artifacts/rsvp-x3-speedtest-validation
```
