# CrossRSVP v0.8.0 — слова из книги в одной строке

CrossRSVP v0.8.0 — обычный пользовательский выпуск для Xteink X3, X4 и X4
Pro. Он сохраняет чтение по страницам и добавляет RSVP: слова из книги
появляются по одному вокруг неподвижной опорной буквы. Релиз публикуется как
GitHub **pre-release / beta**, пока для каждой модели не завершена отдельная
физическая проверка панели.

## Что изменилось

- В RSVP обновляется строка с текущим словом, когда это разрешают обнаруженный
  контроллер и состояние панели. Такой обмен может уменьшить площадь
  обновления и сделать переходы быстрее на конкретном ридере. Полный кадр
  остаётся проверенным запасным путём, если контроллер не подтверждён, область
  строки не подходит или операция не готова.
- Драйверные профили содержат UC8253 для X3 и SSD1677/UC8279 для X4 и X4 Pro.
  При выборе UC8179 на X4 Pro RSVP сохраняет полнокадровый fallback. Для X3
  неуверенный результат probe также ведёт к полному кадру; значение `assumed`
  относится только к конкретному запуску. Нельзя выбирать файл другой модели
  из-за похожего разрешения или названия.
- В инвертированном экране и ночном режиме используется полнокадровое
  обновление; ускоренный путь строки для этих режимов не заявляется.
- RSVP начинается на паузе. Управление скоростью, паузой, возвратом к странице
  и сохранением позиции остаётся общим для кнопок X3/X4 и сенсорного сценария
  X4 Pro.
- Точная скорость зависит от панели, контроллера, LUT, состояния BUSY и
  режима обновления. Обновление строки не обещает одинакового ускорения для
  каждой группы слов или каждой партии экранов.

## Физическое наблюдение X3

Последняя предоставленная проверка выполнена 2026-09-12 на одном X3 в
портретной ориентации. В CSV контроллер указан как `UC8253` с уверенностью
`assumed`; это результат конкретной платы, а не квалификация всей модели.
Пользователь сообщил, что следов предыдущих слов не заметил.

| Вариант | Время | Кадры | Скорость по полному времени | Среднее обновление | Сбои / fallback |
| --- | ---: | ---: | ---: | ---: | --- |
| Полный кадр (`full`) | 60 163 мс | 114 | 113,69 кадра/мин | 489 мс | 0 / 0 |
| Широкая строка (`window`) | 60 056 мс | 130 | 129,88 кадра/мин | 425 мс | 0 / 0 |
| Узкая область (`tight_window`) | 60 115 мс | 130 | 129,75 кадра/мин | 417 мс | 0 / 0 |

Внутри этого одного запуска широкая строка дала на 14,24% больше кадров в
минуту, чем полный кадр; узкая область дала на 14,13% больше полного кадра и
на 0,10% меньше широкой строки. Эти числа относятся к принятым кадрам,
делённым на всё время замера. Интервальные значения CSV используют число
интервалов между кадрами и потому отличаются. Узкая область в этом запуске не
добавила скорости к широкой строке.

Сырые данные сохранены в
`artifacts/rsvp-x3-maxspeed-validation-v0.10.0/hardware-result-2026-09-12-user-01/rsvp-window-test.csv`.
Проверены только один физический X3 и одна ориентация; X4 и X4 Pro на платах
не проверялись. Пользовательское наблюдение об отсутствии следов не заменяет
замеры контраста, ghosting, BUSY, heap, сна, питания и установки. Эти данные
не доказывают максимальную электрическую скорость панели и не переносятся
автоматически на другие партии устройств.

## Статус проверки и публикации

Три model-labelled образа являются отдельными целями выпуска. Их обычные
сборки и локальные пакеты X3, X4 и X4 Pro завершены; результаты сборки,
host/simulator проверок и проверки ресурсов собраны в [отчёте о валидации
v0.8.0](rsvp-v0.8.0-validation.md). Эти проверки не заменяют реальный экран:
до отдельной проверки каждого образа сохраняется
`hardware_qualified: false`; заголовок GitHub может оставаться обычным
`CrossRSVP v0.8.0 — X3, X4 и X4 Pro`, а статус — beta / pre-release. CI и
публикационные проверки выполняются отдельно.

Комплект публикации должен содержать для каждой модели:

- `crossrsvp-x3-v0.8.0.bin`, `crossrsvp-x4-v0.8.0.bin` и
  `crossrsvp-x4pro-v0.8.0.bin`;
- `SHA256SUMS`, `INSTALL.md`, `VALIDATION.md` и
  `firmware-manifest.json` с размером, SHA-256, маркером версии, исходным
  commit и revision FreeInk SDK;
- отдельный статус проверки X3, X4 и X4 Pro без объединения одного физического
  результата в общую квалификацию.

Сайт выбирает точный `.bin` по префиксу модели из опубликованного GitHub
релиза. Предварительные релизы не скрываются: на карточке появляется метка
`beta`. Не следует заранее подменять эти ссылки ссылками на локальные файлы или
диагностические ZIP.
